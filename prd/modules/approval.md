# 확인 요청 (승인) (`APPROVAL`)

## 상태: ✅ 완료 (2026-10-09)

## 목적
파이프라인을 **멈추고 사람에게 내용을 보여 준 뒤** 결정을 받아 이어 가기 (Human-in-the-loop).
예: 여러 회의록을 AI가 정리 → 나에게 보여 줌 → ✅ 승인하면 게시판 등록, 🔁 의견을 주면 AI가 고쳐 다시 보여 줌, ❌ 거절하면 보류 쪽지.

## 출력 (오른쪽 연결점 3개)
| 출력 id | 이름 | 언제 |
|---------|------|------|
| `approve` | 승인 | ✅ 승인 / ✏️ 고쳐서 승인 / (시간 초과 + "승인으로 처리") |
| `retry` | 다시 | 🔁 다시 — **모델 소켓에 AI가 없을 때만** (있으면 노드 안에서 고쳐 다시 물음) |
| `reject` | 거절 | ❌ 거절 / (시간 초과 + "거절로 처리") |

선택되지 않은 출력 쪽 노드는 "건너뜀" (엔진의 분기 실행, `prd/engine-and-editor.md` "분기 실행").

## 파라미터 · 소켓
| name | label | 기본값 | 설명 |
|------|-------|--------|------|
| `title` | 제목 | `확인 요청` | 확인 창 맨 위, `${...}` 가능 |
| `content` | 보여 줄 내용 | `${input}` | 마크다운 — 창에서 제목·표·목록·인용·링크로 보임 |
| `timeoutMin` | 기다릴 시간(분) | 60 | 0 = 결정할 때까지 계속 |
| `onTimeout` | 시간이 지나면 | 거절로 처리 | 거절로 처리 · 승인으로 처리 (의견 "(시간 초과)") |
| `maxRounds` | AI 수정 최대 횟수 | 5 | 넘으면 "다시"는 다시 출력으로 |
| `outputVar` | 출력 변수명 | `approval` | |
| 소켓 `model` | 수정 AI (선택) | | GEMINI_MODEL — 끼우면 "다시" 때 이 노드 안에서 AI가 의견대로 고쳐 다시 물음(반복) |
| 소켓 `instruction` | 수정 지시문 | | AI_INSTRUCTION (여러 개) — 고칠 때의 형식·규칙 |

## 출력 값
- 다음 노드의 `${input}` = **최종 문서** (고쳐서 승인했으면 고친 내용, AI가 고쳤으면 고친 내용)
- `${approval.decision}` = approve | retry | reject · `${approval.feedback}` = 마지막 의견 · `${approval.rounds}` = 몇 번째에 결정했는지

## 동작
1. 내용을 만들고 `ApprovalService` 에 확인 요청을 올린 뒤 **결정이 올 때까지 실행 스레드가 기다림**
   (노드 카드·하단 패널에 🙋 "확인 대기 중", 노드 카드 분홍 깜박임)
2. 🔁 다시 + 모델 소켓 있음 → "AI가 의견을 반영해 다시 쓰는 중…" → Gemini 로 고침
   (시스템: 수정 지시문 + "의견을 정확히 반영해 문서 전체만, 형식 유지") → 고친 내용으로 2번째 확인 요청 (지금까지의 의견 표시)
3. 승인/거절/(AI 없을 때) 다시 → 해당 출력으로 `ctx.route(...)` → 이어서 실행
- 실행을 취소(■ 중지)하면 기다림이 끝나고 확인 요청도 사라짐

## 🙋 확인 창 (`static/js/approvals.js`, 모든 화면)
- 2초마다 `/api/approvals` 확인 → 새 요청이 오면 **창이 저절로 뜸** + 알림음(두 음), 상단 메뉴에 "🙋 확인 요청 N" 배지(깜박임)
- 창: 파이프라인 › 노드 · N번째 / 제목 / **마크다운 내용**(제목·표·목록·들여쓴 목록·인용·코드·굵게·링크) / 지금까지 반영한 의견 /
  의견 입력칸 / ✅ 승인 · ✏️ 직접 고치기(편집 ↔ 미리보기, "고친 내용으로 승인") · 🔁 다시(AI 있으면 "AI가 의견대로 고쳐서 다시 보여 줌") · ❌ 거절,
  마감 시각, 여러 건이면 ‹ › 로 넘기기, ✕ = 나중에(대기는 유지)
- 다시는 의견이 있어야 보냄
- 창을 닫았거나 못 봤을 때 다시 여는 곳 (2026-10-09 추가): 노드 카드의 **🙋 확인하기** 버튼(대기 중일 때만),
  하단 실행 패널 대기 줄의 **🙋 확인 창 열기**, 노드 설정 맨 위 안내 상자(대기 중이면 **확인 창 열기** 버튼), 상단 배지 — 모두 `window.workflowApprovals.open(nodeId)`
- 노드 설정 맨 위에 사용법 안내(`approvalInfo` 파라미터 타입, 2초마다 대기 상태 확인)

## API
| Method | Path | 설명 |
|--------|------|------|
| `GET` | `/api/approvals` | `{pending:[{id, pipelineName, nodeName, title, content, round, aiRevise, history, deadline…}], recent:[최근 결정 30개]}` |
| `POST` | `/api/approvals/{id}` | `{decision: approve\|retry\|reject, feedback?, content?(고쳐서 승인)}` — 이미 끝난 요청이면 410 |

## 예시 파이프라인 "회의록 정리 → 확인 → 게시판 등록" (▶ 실행)
📂 회의록 모으기(폴더) → 🤖 주간 요약 쓰기(Gemini + 요약 형식 지시문) → 🙋 요약 확인(모델 소켓: 수정용 AI, 지시문 소켓: 요약 형식)
→ [승인] 📘 게시판에 등록(`FW팀/회의록/${year}년/${month}월`, 같은 제목이면 내용 바꾸기) → ✉️ 올렸다고 쪽지(`${outline.url}`)
→ [거절] ✉️ 보류 쪽지(`사유: ${approval.feedback}`)
- 실측(브라우저): 요약 창 자동 표시 → 의견 "할 일 표를 담당자별로 묶고 기한 지난 건 ⚠️ 지연" + 🔁 다시 → 2번째 창에 반영본(담당자별·⚠️ 지연 7건)
  → ✅ 승인 → 아웃라인에 반영본 게시 + 쪽지, 보류 쪽지는 건너뜀

## 테스트 (`BranchApprovalTest`)
- 그대로 승인 / 고쳐서 승인(고친 내용이 다음 노드로) / 거절 — 다른 출력 쪽은 건너뜀, 기다리는 동안 노드 상태 waiting
- 다시: AI 없으면 다시 출력 + `${approval.feedback}`, AI 있으면 가짜 Gemini 로 고쳐 2번째 요청(의견·원문·지시문이 프롬프트에) → 승인
- 기다리는 중 실행 취소 → 대기 사라짐

- 확인 요청이 오면 사내 메신저 쪽지로도 알리기 (지금은 화면 창 + 배지 + 소리)
