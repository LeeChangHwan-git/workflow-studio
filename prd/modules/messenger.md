# 사내 메신저 쪽지 (`MESSENGER`)

## 상태: ✅ 완료 (2026-10-09) — 시연용 메신저 포함

## 목적
파이프라인 결과를 **사번**으로 사내 메신저 쪽지로 보낸다 (예: "회의록 요약 올렸습니다", "빌드 실패").
원리는 HTTP 요청과 같다(메신저 API 에 POST) — 시연을 위해 별도 노드로 만들고, 기본값은 **이 앱에 든 시연용 메신저**로 보내
**이 PC 화면 오른쪽 아래에 쪽지 창**이 뜬다. 회사 메신저에 붙일 때는 주소·바디 형식·인증 헤더만 바꾼다.

## 파라미터

| name | label | 기본값 | 표시 조건 | 설명 |
|------|-------|--------|-----------|------|
| `name` | 노드 이름 | `""` | | |
| `empIds` | 받는 사람 사번 | `""` | | 쉼표·공백·`;` 로 여러 명 (중복 제거, 최대 100명), `${...}` 가능 |
| `message` | 메시지 | `${input}` | | 최대 4000자 (시연용 메신저 기준) |
| `sender` | 보내는 사람 이름 | `Workflow Studio` | | |
| `endpoint` | 메신저 API 주소 | `""` | | **비우면 시연용 메신저** `http://127.0.0.1:{포트}/demo-messenger/api/notes` |
| `bodyType` | 요청 바디 | 기본 JSON | | 기본 JSON `{empId, message, sender}` · 직접 구성(회사 메신저 형식) |
| `bodyTemplate` | 바디 형식 | `{"receiver": "${empId}", "content": "${message}", "from": "${sender}"}` | 직접 구성 | `${empId}` `${message}` `${sender}` 는 **JSON 문자열 안에 안전하게**(따옴표·줄바꿈 이스케이프) 들어감. 결과가 올바른 JSON 인지 보내기 전에 확인 |
| `headers` | 요청 헤더 | `""` | | `secretTextarea` — `Authorization: Bearer …` 등 (AI 도우미에게 가림, cURL 붙여넣기 변환 가능) |
| `onFail` | 보내기 실패하면 | 오류로 중단 | | 오류로 중단 · 나머지는 계속 보내고 결과에 기록 |
| `outputVar` | 출력 변수명 | `messenger` | | |

## 동작
- 사번마다 POST 한 번 (회사 메신저 API 는 보통 받는 사람 하나씩), 제한 시간 15초, `Content-Type: application/json`
- 2xx 면 성공, 아니면 실패 (중단 또는 기록). 서버에 연결 못 하면 항상 오류

## 출력
```json
{ "sent": 1, "failed": 0, "demo": true,
  "results": [ { "empId": "20231234", "status": 200, "ok": true,
                 "response": { "ok": true, "id": 1, "to": "홍길동 (FW팀) · 20231234", "shown": true } } ],
  "message": "보낸 내용" }
```

## 원리 — 어디까지 진짜이고 어디가 시연용인가
```
① 요청 (HTTP 메뉴·다른 시스템·다른 파이프라인)
      │  POST /webhook-test/messenger  {"empId":"20231234","message":"…"}
      ▼
② 🪝 웹훅 노드 — 요청을 받아 파이프라인 시작, ${webhook.body.empId} / ${webhook.body.message}
      ▼
③ ✉️ 쪽지 노드 — 사번마다 메신저 API 에 HTTP POST {"empId","message","sender"}
      ▼
④ 시연용 메신저 서버 (이 앱 안, /demo-messenger/api/notes)
      ├─ 사번 → 이름 (시연용 사원 5명)
      ├─ 받은 쪽지함에 저장 (메모리) → /demo-messenger 화면
      └─ 이 PC 화면 오른쪽 아래에 쪽지 창 + 알림음
```

| 부분 | 진짜 / 시연용 |
|------|---------------|
| 파이프라인 → API 로 HTTP 요청 | ✅ 진짜 — 회사 메신저 API 에 보낼 때와 똑같은 방식 (노드 결과에 실제 요청·응답) |
| 메신저 서버 | 🎭 시연용 — 이 앱 안의 작은 서버가 회사 메신저 흉내 |
| 받는 사람 (사번 → 이름) | 🎭 시연용 사원 5명 |
| 쪽지 창 | 🎭 메신저 프로그램·윈도우 알림이 아니라, 앱(자바 서버)이 Swing 으로 직접 그린 창. 색·배치·페이드 인·쌓임은 메신저처럼 보이게 꾸민 것, 알림음은 윈도우 기본 소리 파일 재생. **이 PC 에만** 뜨고 다른 사람에게는 가지 않음 |

→ 실제로 쓸 때는 쪽지 노드의 **API 주소 · 요청 바디(직접 구성) · 인증 헤더** 세 가지만 회사 메신저 것으로 바꾸면 🎭 부분이 진짜 회사 메신저로 바뀐다 (파이프라인의 나머지는 그대로).

## 시연용 메신저 (`DemoMessengerController`, `NotePopup`)
| Method | Path | 설명 |
|--------|------|------|
| `POST` | `/demo-messenger/api/notes` | `{empId, message, sender?}` → 쪽지함에 저장, **나에게 온 쪽지면** 쪽지 창 → `{ok, id, to, toMe, shown}` |
| `POST` | `/demo-messenger/api/me` | `{empId}` — 나(이 PC)의 사번 바꾸기 (⚙ `settings.json` `demo.messengerMyId`, 기본 20240001) |
| `GET` | `/demo-messenger/api/notes` | 쪽지(최신 순, 메모리 최근 100개, `toMe` 표시) + 시연용 사원 목록 + `myId` |
| `DELETE` | `/demo-messenger/api/notes` | 비우기 |
| `GET` | `/demo-messenger` | **쪽지함** 화면 — 📥 나에게 온 쪽지 / 📤 다른 사람에게 간 쪽지(기록만), 오른쪽에서 나의 사번 고르기 (2초마다 새로고침) |

- **나에게 온 쪽지만 쪽지 창** (2026-10-09): 이 PC = 나. 다른 사람에게 보낸 쪽지는 그 사람 PC 에 뜨는 것이므로 이 PC 에는 창을 띄우지 않고 쪽지함에 기록만.
  창에는 받는 사람 대신 "보낸 사람 ○○ · 시각"만 표시
- **크기 조절·이동** (2026-10-11): 가장자리·모서리·◢ 끌기로 크기 조절(크기 기억, 다음 창·재시작 후에도), 머리 끌기로 이동, 머리 더블클릭 → 오른쪽 아래로
- **쪽지 창**: Java Swing (앱에 이미 있음, 추가 설치 없음) — 화면 오른쪽 아래(작업 표시줄 위)에 떠오름(페이드 인),
  파란 머리 "쪽지가 도착했습니다" · 보낸 사람 · 시각 · 내용(줄바꿈·스크롤) · [확인]/✕ 로 닫기,
  여러 개면 위로 쌓임(최대 5개), 윈도우 메신저 알림음(`Windows Notify Messaging.wav`, 없으면 기본음)
- 아이콘(✉ ✕)은 한글 글꼴에 없어 `Segoe UI Symbol` 로 표시
- 화면이 없는 환경(테스트·서버)에서는 창 없이 접수만 (`shown:false`)
- 시연용 사원: **20240001 나 (Workflow Studio)** · 20231234 홍길동(FW팀) · 20220567 김영희(HW팀) · 20210089 이철수(QA팀) · 20190012 박민수(PM) · 20200345 정보안(보안팀).
  목록에 없는 사번도 받음("사번 …"으로 표시)

## 예시 파이프라인 "사내 메신저 쪽지 보내기" (2026-10-09 다른 예시를 모두 지우고 이것만 남김)
웹훅 `/webhook-test/messenger` (전달 내용 구성 비움) → 쪽지 (`empIds: ${webhook.body.empId}`, `message: ${webhook.body.message}`)
```
POST http://localhost:8080/webhook-test/messenger
{"empId": "20240001", "message": "이번 주 회의록 요약이 사내 게시판에 올라갔습니다."}   ← 나에게 보내면 쪽지 창이 뜸
```

- 다른 파이프라인 끝에 붙이기: 예) 회의록 AI 요약 → 아웃라인 등록 → 쪽지 "요약 올렸습니다: ${outline.url}"

## 테스트 (`MessengerModuleTest`, 실제 포트로 기동)
- 주소 비움 → 실제 HTTP 로 시연용 메신저에 전송, 여러 사번·중복 제거, 따옴표·줄바꿈 메시지, 받은 쪽지함·이름 표시·목록에 없는 사번
- 직접 구성 바디(JSON 안전 치환)·Authorization 헤더 → 가짜 회사 메신저, 404 실패 시 중단 / 계속 보내고 기록
- 사번·메시지 없음 안내
- 나에게 온 쪽지만 창 대상(`toMe`), 다른 사람은 `shown:false`, 나의 사번 바꾸기·잘못된 사번 거부
- 웹훅 한글 인코딩: UTF-8(charset 있음/없음), **CP949(charset 없음 — Git Bash·cmd curl, PowerShell 5 등)**, EUC-KR 명시 모두 깨지지 않음
- 실제 화면: 웹훅으로 보내 쪽지 창이 오른쪽 아래에 뜨는 것을 화면 캡처로 확인
