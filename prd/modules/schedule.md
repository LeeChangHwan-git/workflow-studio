# 타이머 (`SCHEDULE`)

## 상태: ✅ 완료 (2026-10-03)

## 목적
원하는 시각·간격마다 파이프라인을 자동으로 시작하는 **트리거** (n8n Schedule Trigger와 같은 개념).
예: 평일 09:00에 AI에게 "오늘의 먹거리 트렌드"를 물어 md 파일로 저장.

## 파라미터

| name | label | 기본값 | 표시 조건 | 설명 |
|------|-------|--------|-----------|------|
| `name` | 노드 이름 | `""` | | |
| `active` | 타이머 | 꺼짐 | | 켜짐/꺼짐. 켜고 **저장**해야 동작 |
| `mode` | 실행 방식 | 일정 간격 | | 일정 간격 · 매일·요일 지정 시각 · 고급 (cron) · 한 번만 |
| `intervalValue` / `intervalUnit` | 간격 / 단위 | 5 / 분 | 일정 간격 | 분·시간, **최소 1분**, 최대 31일 |
| `days` | 요일 | 매일 | 매일·요일 | 매일 · 평일(월~금) · 주말(토·일) · 월요일~일요일 |
| `time` | 시각 | `09:00` | 매일·요일 | 24시간 `HH:mm` (`9:05`도 허용) |
| `cron` | cron 식 | `0 9 * * MON-FRI` | 고급 | 리눅스식 5자리(분 시 일 월 요일) 또는 Spring 6자리(초 포함) |
| `onceAt` | 날짜·시각 | `""` | 한 번만 | `2026-10-05 09:00`. 지난 시각이면 실행 안 함 |
| `message` | 전달 내용 | `""` | | 비우면 실행 정보 JSON, 채우면 그 텍스트를 다음 노드로 (`${date}` `${time}` `${datetime}` `${firedAt}`) |
| `scheduleInfo` | 상태 | - | | 아래 "설정 화면" |
| `outputVar` | 출력 변수명 | `timer` | | |

출력 (전달 내용이 비었을 때):
```json
{ "firedAt": "2026-10-03T20:59:34", "trigger": "timer", "schedule": "1분마다" }
```
`trigger`: `timer`(정해진 시각) · `now`(지금 실행 버튼) · `manual`(툴바 ▶ 실행).

## 동작 (`ScheduleService`)
- **등록**: 저장된 파이프라인에서 `active=켜짐`인 타이머 노드를 찾아 등록 — 서버 기동 시, 파이프라인 저장·삭제·가져오기 시
  (`PipelineService`가 `PipelinesChangedEvent` 발행), 그리고 **1분마다 재확인**
- 설정이 바뀐 타이머만 다시 등록 (그대로면 유지 → 간격 방식의 기준 시각이 흔들리지 않음)
- 간격 방식은 **등록 시각 기준**으로 이어짐 (예: 09:07 등록, 15분 간격 → 09:22, 09:37 …)
- **겹침 방지**: 같은 타이머의 이전 실행이 아직 진행 중이면 이번 회차는 건너뜀 (기록에 "건너뜀")
- **놓친 회차는 실행하지 않음**: 서버가 꺼져 있던 동안의 회차를 몰아서 실행하지 않음 (n8n과 같음)
- 꺼진 타이머는 정해진 시각에 실행되지 않음 (지금 실행 버튼은 꺼져 있어도 가능 — 테스트용)
- 실행은 `RunMode.SCHEDULE`, 이 타이머에서 화살표로 이어진 노드만 실행
- 전용 스케줄러 스레드 2개(데몬). 실제 파이프라인 실행은 실행 엔진의 별도 스레드

## 설정 화면 (상태)
- **⏰ 설명 + 다음 실행 3개**: 저장된 그대로 동작 중이면 실제 등록된 시각, 화면에서 바꿨으면 바꾼 값 기준 미리보기 (오류면 ❌ 이유)
- **등록 상태**: ● 동작 중 / 💾 저장하면 시작됩니다 / ○ 꺼짐 / ❌ 등록 실패
- **▶ 지금 한 번 실행**: 저장된 파이프라인을 이 타이머로 즉시 실행하고 하단 패널에 결과 표시
- **최근 실행**: 시각 · 타이머/수동 · ✓ 실행 / 건너뜀 / 오류, **보기**로 그 실행 결과 다시 표시
  (저장: `{storage}/schedules/{파이프라인id}_{노드id}.json`, 최근 100건)
- 캔버스 카드: 켜져 있으면 초록 테두리 + "● 타이머 ON"

## 달력 연동 (2026-10-04)
- 상단 **달력**에 타이머 일정이 함께 표시됨 (`ScheduleService.calendar(from, to)` → `CalendarController` 의 `timersJson`)
  - **예정**(보라 점선 ⏰): 켜져 있는 타이머의 앞으로 실행 시각 — 실제 등록된 일정 계산과 같은 로직(간격 기준 시각 포함)
  - **지난 실행**: 실행 기록 파일 기준 — ✓ 실행됨(초록) / ✗ 오류(빨강: 기록 오류 또는 실행 상세가 메모리에 남아 있고 파이프라인이 오류로 끝난 경우) / – 건너뜀(회색)
  - 하루에 같은 타이머가 3번보다 많으면 "00:03~23:58 288회" 한 줄로 묶음
- 칸에는 일반 일정과 합쳐 최대 3줄 + "+N개 더", 날짜를 누르면 오른쪽 패널에 "⏰ 파이프라인 타이머 N건"
  (시각·상태·지금 실행 여부·파이프라인 링크·일정 설명·오류 메시지)
- 달력 상단 **⏰ 타이머 표시** 체크로 숨기기/보이기 (브라우저에 기억)
- 화면에 보이는 범위(첫 주 일요일 ~ 마지막 주 토요일) 전체를 계산 — 지난 달·다음 달 칸에도 표시

## API
| Method | Path | 설명 |
|--------|------|------|
| `POST` | `/api/schedule/{pipelineId}/{nodeId}/status` | body = 화면의 현재 설정 → `{registered, error, description, next, history, preview}` (새 파이프라인은 pipelineId `new`) |
| `POST` | `/api/schedule/{pipelineId}/{nodeId}/run-now` | 지금 한 번 실행 → `{executionId}` / `{skipped, message}` |
