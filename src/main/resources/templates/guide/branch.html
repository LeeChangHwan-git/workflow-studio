🔀 분기 표현식 설명서

분기 노드는 값을 규칙으로 검사해서, 맞는 규칙의 출력(오른쪽 연결점)으로만 다음 노드를 실행합니다. 맞는 규칙이 없으면 그 외로 갑니다. 선택되지 않은 쪽 노드는 실행 기록에 "건너뜀"으로 남습니다.
동작 방식검사할 값연산자식 (고급) 정규식여러 규칙이 맞으면예시 모음자주 묻는 것

동작 방식

웹훅 ─▶ 🔀 분기 ─[1 포함]──▶ A 처리 ├[2 포함]──▶ B 처리 └[그 외]───▶ 기본 처리
  • 규칙 하나 = 노드 오른쪽 출력 하나 (+ 맨 아래 그 외). 규칙 이름이 출력 이름이 되고 화살표에도 표시됩니다.
  • 분기 노드는 받은 값을 그대로 다음 노드에 넘깁니다 (다음 노드의 ${input} 은 분기 전과 같음).
  • 맞은 규칙 이름은 ${branch.matched} (출력 변수명이 branch 일 때) 로 쓸 수 있습니다.
  • 설정 패널의 🧪 시험해 보기에 예시 값을 넣으면 실제 실행과 같은 판정으로 어느 출력으로 갈지 바로 보입니다.

검사할 값

기본은 ${input} — 앞 노드가 넘긴 값 전체. 일부만 보고 싶으면 변수 경로를 씁니다.

쓰는 법뜻
${input}앞 노드 출력 전체
${webhook.body.type}웹훅으로 받은 JSON 의 type 값 (전달 내용 구성을 비웠을 때)
${page.count}웹 페이지 추출 결과의 개수
${approval.decision}확인 요청의 결정 (approve / retry / reject)
규칙마다 "+ 이 규칙만 다른 값 검사"를 누르면 그 규칙만 다른 값을 볼 수 있습니다. 예) 1번 규칙은 제목, 2번 규칙은 작성자.

연산자

연산자뜻예 (비교값 → 검사할 값)
포함값 안에 비교값이 들어 있음1 → "주문 1번" 맞음
포함하지 않음들어 있지 않음긴급 → "일반 문의" 맞음
같음 / 다름앞뒤 공백을 뺀 값이 똑같은지FW → " FW " 같음
~로 시작 / ~로 끝남앞(뒤)이 비교값[긴급] → "[긴급] 서버 장애" 시작
다음 중 하나 포함쉼표로 적은 것 중 하나라도 들어 있음긴급, 장애, 오류 → "결제 오류 발생" 맞음
정규식에 맞음패턴 검색 (아래 정규식)^\d{8}$ → "20231234" 맞음
비어 있음 / 비어 있지 않음공백만 있어도 "비어 있음"(비교값 없음)
숫자 > ≥ < ≤ =값을 숫자로 읽어서 비교. "1,234", "85점"처럼 쉼표·단위가 붙어도 숫자 하나면 읽음. 숫자가 아니면 맞지 않음80 숫자 ≥ → "85점" 맞음
글자 수 > / <앞뒤 공백을 뺀 글자 수100 글자 수 > → 긴 글 맞음
식 (고급)여러 조건을 한 줄로 (아래)#value.contains('FW') and #num > 3

글자 비교는 기본으로 대소문자 무시 (fw = FW). 노드 설정 "글자 비교"에서 바꿀 수 있습니다.

식 (고급)

조건을 여러 개 묶거나 JSON 안의 값을 비교할 때 씁니다. 결과는 반드시 참/거짓이어야 합니다.

안전을 위해 읽기 전용으로만 동작합니다 — 프로그램 실행, 파일 접근, 새 객체 만들기(T(...), new ...) 는 오류가 납니다.

정규식 짧은 정리

패턴뜻

[가-힣]+한글 한 글자 이상
A|BA 또는 B

예: 사번 8자리 ^\d{8}$ · 날짜 \d{4}-\d{2}-\d{2} · 메일 [\w.]+@[\w.]+

여러 규칙이 맞으면

설정동작
처음 맞는 규칙 하나만 (기본)위에서부터 검사해 처음 맞는 출력 하나로만. 순서가 중요 — 좁은 조건을 위에 (↑↓ 로 순서 바꾸기)
맞는 규칙 모두맞는 출력 모두로 동시에 (예: "FW 관련"이면서 "긴급"이면 두 쪽 다 실행)
